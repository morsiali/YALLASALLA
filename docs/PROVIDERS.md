# Provider interfaces and the mock / sandbox / live boundary

All integrations sit behind small interfaces in `server/src/providers/index.ts`. `buildProviders(cfg)` wires adapters; `buildApp({ providers })` lets tests inject others. The UI shows a **"Demo build: test-mode integrations"** banner and per-feature labels whenever a mock or sandbox adapter is active; `GET /api/config` and the admin _Providers_ page expose **modes only, never secrets**.

| Capability      | Interface                                      | Shipped adapter(s)                                                                                                                | Mode label            | To go live                                                                                                                                                                                                                                                                                                                                              |
| --------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phone OTP       | `OtpProvider { mode; generateCode(); send() }` | `MockOtpProvider` (fixed code `123456`, nothing sent)                                                                             | `mock`                | Implement `send()` with an SMS/verify provider, generate random codes. **Production start-up refuses the mock.** Keep the attempt counter/rate limits (already enforced server-side).                                                                                                                                                                   |
| Payments        | `PaymentProvider { charge(); refund() }`       | `SandboxPaymentProvider` (tokens `tok_success`, `tok_decline`, `tok_pending`, `tok_network`) + cash on delivery                   | `sandbox`             | Use the PSP's **hosted fields / tokenization** so raw card data never reaches this server; pass the token + idempotency key; implement `refund`; point the PSP webhook at `POST /api/webhooks/payments` (HMAC `x-signature` over the raw body, idempotent on `eventId`). Map PSP event ids/refs to `{eventId, ref, status}`.                            |
| AI helper       | `AiProvider { enhanceParse() }`                | `RulesOnlyAi` (default) and `AnthropicAi` (optional; `AI_PROVIDER=anthropic` + `ANTHROPIC_API_KEY`, model from `ANTHROPIC_MODEL`) | `rules` / `anthropic` | The adapter only returns constraint hints for a free-text request; output is validated with a strict schema, can only fill fields the rules parser missed, and any error falls back to rules (flagged). It never supplies products, prices, stock or reasons. **The Anthropic adapter has not been exercised against the live API in this repository.** |
| Transcription   | `TranscriptionProvider { transcribe() }`       | `MockTranscription` (returns the tester-typed text, supports `[?word?]` uncertainty markers, labelled TEST MODE)                  | `mock`                | Implement against an STT service; return faithful text, an optional readable version, detected language and uncertain words (do not guess). Keep the consent check, retention (`retention_until`) and "audio stays available" behaviour.                                                                                                                |
| Storage         | `StorageProvider { put(); get(); delete() }`   | `LocalStorage` (filesystem under `STORAGE_DIR`, path-traversal safe)                                                              | local                 | Add an S3-compatible adapter; keep access control in the API (signed, expiring `/api/media/:id` links) or switch to provider-signed URLs. Back up media with the database.                                                                                                                                                                              |
| Geo             | `GeoProvider { nearest() }`                    | `OfflineGeo` (nearest seeded area centre by haversine; coordinates are never stored)                                              | `mock`                | Optional: add address search/geocoding. Manual area entry must remain available.                                                                                                                                                                                                                                                                        |
| Notifications   | in-app rows + `EventBus` (SSE)                 | in-app + live events                                                                                                              | in-app                | For push: register device tokens (`POST /api/me/devices` exists) and add a sender in `services/common.ts → notify()` (FCM/APNs). Email/SMS likewise.                                                                                                                                                                                                    |
| Analytics       | `analytics_events` table                       | DB adapter, no PII in properties                                                                                                  | local                 | Export to a warehouse; keep consent gating for personalisation.                                                                                                                                                                                                                                                                                         |
| Maps / tracking | —                                              | none (no live courier map is simulated)                                                                                           | n/a                   | Out of scope for the MVP.                                                                                                                                                                                                                                                                                                                               |

Idempotency contract: orders (`Idempotency-Key` header + unique `(customer_id, idempotency_key)`), payments (`payments.idempotency_key` unique, provider call keyed `pay:<user>:<key>`), refunds (provider key includes order/amount/reason), loyalty entries (`loyalty_ledger.idempotency_key` unique), webhooks (`payment_events.event_id` primary key).
