# F. Acceptance tests

Every criterion below is checked by an **automated test that runs in CI** against a real PostgreSQL (server tests) or a real Chromium browser (end-to-end). Nothing here is a manual checklist.

Run them:

```bash
npm run db:local:start            # or: docker compose up -d db
npm run test:server               # 122 tests: domain, RLS/policies, API, payments, loyalty, messaging, merchant, admin, backup/restore
npm run test:web                  # i18n completeness, grammar, money formatting
cd web && npx playwright install chromium && cd ..
npm run test:e2e                  # 13 browser tests (EN/AR, mobile, accessibility)
```

## What the tests do **not** prove

- Native Android/iOS builds, store signing and push notifications (not built here).
- Behaviour with live SMS, payment, transcription or AI providers (adapters are test/sandbox; the AI adapter validates output with a schema but was not exercised against the live API).
- Performance at scale, multi-instance behaviour (in-memory rate limiter and SSE bus), or load.
- Usability with real UAE customers and merchants (interview plan in `docs/01-PRODUCT.md`).
- Legal/regulatory compliance.
